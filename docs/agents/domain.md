# Domain documentation

This is a single-context repository.

Before exploring a domain area:

1. Read `CONTEXT.md`.
2. Read relevant decisions under `docs/adr/`.
3. Use the glossary’s canonical terms in issues, tests, hypotheses, and code.
4. Surface conflicts with an ADR explicitly instead of silently overriding it.

Domain files are created and updated lazily as terminology or durable architectural decisions are
resolved.
